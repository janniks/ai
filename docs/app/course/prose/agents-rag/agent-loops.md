Strip the frameworks away and an agent is a loop: the model receives a goal plus the history of its actions and their results, emits either a tool call or a final answer, and the loop executes and appends. Planning, memory, and tool use are names for what fills the context at each iteration.

The distinction worth keeping from Anthropic's piece: a workflow fixes the control flow in code and uses the model inside it; an agent lets the model direct its own steps. Workflows are predictable and debuggable; agents buy flexibility at the price of compounding errors. Write $p$ for the chance one step goes right, a number between 0 and 1.
