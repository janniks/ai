During generation, the keys and values of all previous tokens are cached so each new token costs one forward pass over itself, not the whole prefix. The cache is large: $2 \times n_\text{layers} \times n_\text{heads} \times d_\text{head} \times T$ values per sequence, and at long contexts it, not the weights, dominates memory. This is why grouped-query attention and DeepSeek's latent attention exist; both are compressions of exactly this object.

The other number to internalize: generating one token reads every weight from memory once, roughly $2N$ FLOPs against $N$ parameters of traffic. Modern GPUs do hundreds of FLOPs in the time they load one byte, so single-stream decoding leaves the compute units mostly idle. Batching, speculative decoding, and the kernels of the next concept are all ways to buy arithmetic with bandwidth already spent.
