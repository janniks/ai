Write the loss as $\mathcal{L}(\theta)${tip:Read this as the loss L as a function of theta. Theta stands for all the adjustable numbers in the network, and the loss is one single number measuring the average error the network makes across the training examples. Lower means better, so all of training is just an effort to push this one number down.}: one number, depending on the parameters $\theta$, that says how wrong the network currently is. The gradient, written $\nabla_\theta \mathcal{L}${tip:Read this as nabla theta of L, the gradient of the loss with respect to the parameters. The upside-down triangle is just a symbol meaning a list with one entry per parameter, where each entry says how much a tiny increase in that parameter would raise or lower the error. It matters because it tells you, for every knob at once, which way to turn it to make the network less wrong.}, lists for each parameter how the error responds to nudging it. Training repeatedly steps every parameter the other way: $\theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}${tip:Read the arrow as becomes. The new parameters become the old parameters minus eta times the gradient, where the gradient points in the direction that would increase the error and eta is a small number controlling the step size. Subtracting moves every parameter a tiny step downhill, and repeating this millions of times is literally what training is.}, where the small number $\eta$ (eta) is called the learning rate.

In practice the gradient is estimated on a small random batch of examples rather than the whole dataset. The estimate is noisy, but the noise is tolerated, and arguably helpful, in exchange for many more updates per unit of compute. Adam, the default optimizer for the models ahead, smooths the steps over time and gives each parameter its own step size, so all of them move at comparable speeds.
